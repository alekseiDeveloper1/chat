# Chat

Мобильный P2P-чат для обмена сообщениями и файлами в общей комнате. Приложение написано на React Native и Expo SDK 54, а навигация построена на Expo Router.

## Возможности

- Подключение к комнате по общему имени и паролю.
- Обмен сообщениями через прямой WebRTC DataChannel. MQTT используется для сигнализации и установления соединения.
- Локальная история сообщений в SQLite на устройстве.
- Шифрование содержимого сообщений AES с ключом, полученным из пароля комнаты.
- Отправка вложений размером до 5 МБ и приём текста и файлов через системное меню «Поделиться».
- Автоматическое восстановление соединения и отображение событий подключения в приложении.
- Системные уведомления о новых сообщениях и прием сообщений в свернутом Android-приложении, пока открыта комната.

Оба участника должны указать одинаковые имя комнаты и пароль. Сервер MQTT помогает установить P2P-соединение; содержимое сообщений передаётся через WebRTC DataChannel.

## Требования

- Node.js 20.19.x или новее в линейке 20.x.
- Android Studio и Android SDK для сборки Android-приложения.
- macOS и Xcode 16.1 или новее для локальной сборки iOS-приложения.
- Для запуска в Expo Go доступен ограниченный набор возможностей; нативные модули WebRTC и приёма системных пересылок требуют development build.

Проект использует Expo SDK 54, React Native 0.81 и React 19.1. Перед установкой или обновлением Expo-пакетов сверяйтесь с [документацией Expo SDK 54](https://docs.expo.dev/versions/v54.0.0/).

## Установка и запуск

```bash
yarn install
npx expo start
```

Откройте проект в установленном development build или запустите нативную сборку:

```bash
# Android: устройство или эмулятор
yarn android

# iOS: симулятор (только macOS с установленным Xcode)
yarn ios

# Web
yarn web
```

Для подключения через туннель:

```bash
yarn tunnel
```

## Сборка APK

Перед сборкой установите зависимости и обновите нативный Android-проект после изменений Expo-конфигурации:

```bash
yarn install
npx expo prebuild --platform android --no-install
```

Соберите APK из корня проекта. Для Windows используйте `gradlew.bat`, для macOS/Linux — `./gradlew`:

```powershell
# Windows PowerShell: отладочный APK
cd android
.\gradlew.bat assembleDebug

# Release APK
.\gradlew.bat assembleRelease
```

```bash
# macOS/Linux: отладочный APK
cd android
./gradlew assembleDebug

# Release APK
./gradlew assembleRelease
```

Готовые файлы появятся в `android/app/build/outputs/apk/debug/` и `android/app/build/outputs/apk/release/`. Сейчас release-вариант подписывается отладочным ключом из Android-проекта, поэтому подходит для установки и проверки, но перед публикацией в магазине настройте собственный ключ.

При первом запуске Android-команды Expo сгенерирует/обновит нативный проект и установит приложение на подключённое устройство или эмулятор. После изменения конфигурации Expo-плагинов пересоберите development build.

## Уведомления и фоновый прием

При входе в комнату приложение запрашивает разрешение на уведомления. Для каждого нового входящего сообщения появляется уведомление со звуком и кратким текстом; для сообщения только с вложением — имя файла. История, собственные сообщения и повторная доставка недавно полученного пакета в текущей сессии не создают новых уведомлений. Ошибки уведомлений видны в журнале приложения без содержимого переписки.

На Android во время подключения к комнате работает foreground service с постоянным уведомлением. Она сохраняет выполнение JavaScript и P2P-соединение при сворачивании и смахивании приложения из списка последних приложений, пока Android сохраняет процесс и доступ к сети. Активная сессия чата живёт независимо от экрана: входящие сообщения сохраняются и вызывают уведомления даже без открытого интерфейса. При повторном открытии показывается та же комната с обновлённой историей. При явном выходе из комнаты или окончательном сбое восстановления соединения служба останавливается.

Уведомления используют отдельный канал «Сообщения чата», его звук и показ можно изменить в системных настройках. Нажатие на уведомление возвращает в приложение. Для длительной работы с выключенным экраном разрешите фоновую работу и отключите оптимизацию батареи для приложения в настройках Android; названия пунктов зависят от устройства.

После установки зависимостей **обновите нативный проект и пересоберите приложение** (обычного перезапуска Metro недостаточно):

```bash
yarn install
npx expo prebuild --platform android --no-install
yarn android
```

Плагин `plugins/withChatBackgroundService.js` добавляет тип службы `remoteMessaging`, необходимые разрешения и `stopWithTask=false` при prebuild. Работа требует нативной сборки; для проверки без компьютера используйте release APK из раздела «Сборка APK». Expo Go не содержит модуль фоновой службы.

Проверка на двух Android-устройствах:

1. Войдите в одну комнату, разрешите уведомления и дождитесь P2P-соединения.
2. Сверните приложение получателя, затем смахните его из списка последних приложений. Постоянное уведомление фоновой службы должно остаться.
3. Отправьте текст и файл со второго устройства. Проверьте уведомления, в том числе с заблокированным экраном получателя.
4. Откройте приложение через уведомление: комната и полученные сообщения должны отображаться без повторного подключения и повторных уведомлений.
5. Выйдите из комнаты: постоянное уведомление должно исчезнуть, приём должен остановиться. Проверьте также отказ в разрешении на уведомления: чат должен продолжить работать.

Ограничения: «Принудительно остановить» в настройках Android, остановка приложения через системный список активных служб, уничтожение процесса системой и перезагрузка разрывают P2P-соединение. После этого нужно снова открыть приложение и войти в комнату. Даже при включённом интернете Doze и ограничения энергосбережения производителя могут приостановить доступ приложения к сети. На iOS локальные уведомления показываются для сообщений, полученных работающим приложением, но длительный фоновый P2P-прием не реализован. Для доставки при приостановленном/завершенном процессе нужен серверный путь push через FCM/APNs (например, Expo Push Service); сервер сообщений и регистрация push-токенов в этом P2P-проекте отсутствуют. Фоновый таймер или `expo-background-task` эту задачу не решают.

Основа реализации: [уведомления Expo SDK 54](https://docs.expo.dev/versions/v54.0.0/sdk/notifications/), [Android foreground services](https://developer.android.com/develop/background-work/services/fgs/service-types#remote-messaging), [stopWithTask](https://developer.android.com/guide/topics/manifest/service-element#stop), [ограничения Doze](https://developer.android.com/training/monitoring-device-state/doze-standby).

## Настройки комнаты

Имя комнаты и пароль можно задать переменными окружения `EXPO_PUBLIC_ROOM_NAME` и `EXPO_PUBLIC_ROOM_PASSWORD`. Если они не заданы, приложение использует значения по умолчанию из экрана подключения.

Для дополнительного пространства имён MQTT-топиков можно задать `EXPO_PUBLIC_MQTT_USER`. Без этой переменной используется корневой префикс брокера. Адрес брокера и STUN-сервер заданы в `src/data/network/networkConstants.ts`.

Переменные с префиксом `EXPO_PUBLIC_` встраиваются в клиентское приложение и доступны пользователям сборки. Не помещайте в них секреты или учётные данные, которые должны оставаться конфиденциальными.

Локально создайте `.env` в корне проекта, например:

```dotenv
EXPO_PUBLIC_ROOM_NAME=my-room
EXPO_PUBLIC_ROOM_PASSWORD=use-a-long-unique-passphrase
EXPO_PUBLIC_MQTT_USER=my-app
```

Не коммитьте `.env` и не используйте один пароль для приватных разговоров с разными участниками. Чтобы два клиента попали в одну комнату, им нужны одинаковые имя комнаты и пароль.

## Структура проекта

```text
src/
├── app/             # маршруты Expo Router и обработка входящей пересылки
├── application/     # активная сессия чата независимо от экрана
├── data/            # SQLite, шифрование, файлы, MQTT и WebRTC
├── domain/          # сущность сообщения и логика чата
├── presentation/    # экран чата, хуки и обработка пересылок
└── shared/          # ссылки и журнал событий
```
